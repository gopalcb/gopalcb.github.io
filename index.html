Custom tools and runtime for agent work

The framework keeps an agent run easy to follow: requests become messages, known tools do bounded work, the runtime saves useful state, and memory helps the next run start cleaner. The diagrams below show that flow first, then use the diagram builder as the main example.

01 / Initial Agent Surface

Start with the runtime pieces the agent can trust

The first layer is intentionally small: messages move requests, handlers call known tools, memory keeps useful work, and the runtime ties it together.

Agent messagingDurable envelopes with topic, sender, payload, result, and inspectable state.
Custom toolsSmall direct tools for browser checks, search, feedback, diagrams, and local work.
Basic memoryJSON records for task, summary, validation, files, and retrieval by simple search.
RuntimeWorkflow resolution, MQ dispatch, memory, and tool calls behind one compact facade.
02 / Tool Calls Through Messages

Tool calls ride inside durable messages

A caller posts intent. MQ turns it into an event. A topic handler does bounded work. The result becomes state an operator or another agent can inspect.
